Configuration files

Everything lives in ~/.culler/:

PathContents
sources.confthe saved sources (tab-separated; Immich API keys are not here — they live in the OS keychain)
export.confthe JPEG export preset
update.confthe update check's last result, and disabled=1 when you've turned it off (Settings → General — adding the line by hand does the same)
destinations.confthe pinned sort folders, in digit order, each with its Move/Copy choice (tab-separated)
settings.confthe Settings that have no other home, one key=value per line — written by the Settings sheet, read at launch (a hand edit applies on the next launch; lines culler doesn't know are kept)
state/per-server culling state for Immich sources (the write-through queue's source of truth; develop + crop per asset)
cache/disk cache of remote previews and embedded RAW previews (4 GB by default — Settings → Storage sets the limit or clears it; least-recently-used eviction)
logs/culler.logthe diagnostic log (below)

Environment overrides: CULLER_CONFIG_DIR and CULLER_CACHE_DIR relocate the above; CULLER_IMMICH_URL + CULLER_IMMICH_KEY inject a temporary Immich source for one session without persisting anything.

The diagnostic log

culler keeps a plain-text trace of what it did at ~/.culler/logs/culler.log — one line per thing you did or the app decided, never per frame: the source you opened, what the scan found, the photo you focused (its asset ids, crop, grade, whether it fronts a culler edit and what the server's saved copy of the grade says), every edit you committed, every step of a J (which file it rendered from, what crop and grade it applied, the upload id, what replaced what in the stack, whether the grade saved), every batch you ran from the apply panel (the [apply] lines: what was dispatched on how many photos and where to, one line per photo saying whether it was copied, moved, trashed, exported, downloaded, archived or uploaded — or why it failed — a line when you cancel, and a closing count with the time it took), every sort-mode send (the [sort] lines: entering and leaving sort mode, pinning and unpinning folders, each press queued, each move or copy dispatched, and what happened to every photo — sent, already in the folder, or refused because the folder wasn't reachable), the background check of your unsaved server edits (the [unsaved] lines: when the check starts and how many photos it has to look at, each photo it proves saved or forgets because the server no longer has it, and a closing tally), the moment grouping (the [burst] lines: how many moments the library holds each time it's grouped and the gap it used, which moment N dealt, and every Enter keep-one with what it picked and rejected), the settings culler started with and every change you make to them (the [settings] lines — one per change, naming the values that moved, not one per step of a drag), every pivot (the [pivot] lines: what you pivoted to and from where, how many photos it showed, and how it ended — back, stay, or closed because the library changed), every change to the grid's grouping (the [grid] lines: by day, by moment or none, and how many groups it made), and every server hiccup. Nothing in it identifies your photos beyond file names and server ids. It is small (rotated at 8 MB, one backup kept) and always on.

When something looks wrong — an upload that doesn't match what you saw, an edit that didn't come back — the log is the first thing to send along with the report. Settings → General → Show log file (Cmd+,) shows it in Finder, ready to attach; from a terminal:

tail -200 ~/.culler/logs/culler.log

Launch with --verbose (or CULLER_LOG=1 in the environment) to mirror every line to the terminal as it happens.

Known limitations

  • Old Sony ARW files embed only a 1616×1080 preview — that's the best a RAW-only ARW can display while culling (the develop panel demosaics the RAW itself, at full quality).
  • Match Look's Temp slider doesn't link across a set that mixes RAW and JPEG-only photos (Tint does).
  • Inside a Match Look session, nothing — tone, matched crops, gray-point samples — touches disk until M commits; a member is pre-placed from the reference's frame only while it carries no crop of its own (Reset in the pass re-places deliberately).
  • A crop window extended past the photo's edges (white padding) is stored honestly in the standard fields, but other editors reading the sidecar may clamp it back to the frame.
  • After J on an Immich photo that has no RAW file, the uploaded render becomes the photo culler shows — plain, exactly as rendered. Editing it again (a new crop or grade on top) isn't supported yet: a further J re-uploads the same picture.
  • Lens correction reads the camera's own embedded parameters (Sony ARW). RAWs from other makes develop uncorrected for now, so their framing can drift slightly from the corrected camera JPEG's.
  • Develop and crop on an Immich source stay local until you export or upload; only ratings, flags and labels sync live.
  • Upload to Immich copies — there is no "move" yet, deliberately (see batch operations).
  • The app is exercised primarily on macOS so far; a Windows validation pass is on the roadmap.
