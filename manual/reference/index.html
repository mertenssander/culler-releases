Configuration files

Everything lives in ~/.culler/:

PathContents
sources.confthe saved sources (tab-separated; Immich API keys are not here — they live in the OS keychain)
export.confthe JPEG export preset
state/per-server culling state for Immich sources (the write-through queue's source of truth; develop + crop per asset)
cache/disk cache of remote previews and embedded RAW previews (4 GB, least-recently-used eviction)
logs/culler.logthe diagnostic log (below)

Environment overrides: CULLER_CONFIG_DIR and CULLER_CACHE_DIR relocate the above; CULLER_IMMICH_URL + CULLER_IMMICH_KEY inject a temporary Immich source for one session without persisting anything.

The diagnostic log

culler keeps a plain-text trace of what it did at ~/.culler/logs/culler.log — one line per thing you did or the app decided, never per frame: the source you opened, what the scan found, the photo you focused (its asset ids, crop, grade, whether it fronts a culler edit and what the server's saved copy of the grade says), every edit you committed, every step of a J (which file it rendered from, what crop and grade it applied, the upload id, what replaced what in the stack, whether the grade saved), and every server hiccup. Nothing in it identifies your photos beyond file names and server ids. It is small (rotated at 8 MB, one backup kept) and always on.

When something looks wrong — an upload that doesn't match what you saw, an edit that didn't come back — the log is the first thing to send along with the report:

tail -200 ~/.culler/logs/culler.log

Launch with --verbose (or CULLER_LOG=1 in the environment) to mirror every line to the terminal as it happens.

XMP fields

Sidecars are edited in place — fields written by other tools survive.

FieldMeaning
xmp:Ratingstars 0–5; −1 marks a reject (per the XMP spec)
xmp:Labelcolor label name
culler:Flagpick / reject / none
crs:Exposure2012, crs:Contrast2012, crs:Highlights2012, crs:Shadows2012basic tone
crs:IncrementalTemperature, crs:IncrementalTintwhite balance while developing a JPEG (the non-raw form)
crs:Temperature, crs:Tintwhite balance while developing a RAW (real Kelvin; absent = As Shot)
culler:DevelopMode"Raw" when the photo carries RAW-mode WB edits
crs:LensProfileEnable"0" when in-camera lens correction is turned off (absent = on)
crs:LuminanceSmoothing (+ ColorNoiseReduction)grain reduction while developing a RAW (absent = ISO-scaled automatic)
crs:Vibrance, crs:Saturationpresence
crs:ParametricHighlights/Lights/Darks/Shadowstone curve regions
crs:PostCropVignetteAmount (+ Style)vignette
crs:HasCrop, crs:CropLeft/Top/Right/Bottom, crs:CropAnglecrop + straighten
culler:OrientationQuarter90° turns (the crs: schema has no field for them)
culler:History, culler:Snapshotsthe photo's edit history + named snapshots (undo/redo; culler-private)

Known limitations

  • Old Sony ARW files embed only a 1616×1080 preview — that's the best a RAW-only ARW can display while culling (the develop panel demosaics the RAW itself, at full quality).
  • Match Look's Temp slider doesn't link across a set that mixes RAW and JPEG-only photos (Tint does).
  • Inside a Match Look session, nothing — tone, matched crops, gray-point samples — touches disk until M commits; a member is pre-placed from the reference's frame only while it carries no crop of its own (Reset in the pass re-places deliberately).
  • A crop window extended past the photo's edges (white padding) is stored honestly in the standard fields, but other editors reading the sidecar may clamp it back to the frame.
  • After J on an Immich photo that has no RAW file, the uploaded render becomes the photo culler shows — plain, exactly as rendered. Editing it again (a new crop or grade on top) isn't supported yet: a further J re-uploads the same picture.
  • Lens correction reads the camera's own embedded parameters (Sony ARW). RAWs from other makes develop uncorrected for now, so their framing can drift slightly from the corrected camera JPEG's.
  • Develop and crop on an Immich source stay local until you export or upload; only ratings, flags and labels sync live.
  • Upload to Immich copies — there is no "move" yet, deliberately (see batch operations).
  • The app is exercised primarily on macOS so far; a Windows validation pass is on the roadmap.
