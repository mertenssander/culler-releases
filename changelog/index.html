Changelog

0.5.0 — 2026-08-02

culler now tells you when there's a new culler — plus a batch of fixes and polish straight from the same live-server field session.

  • Update notice. On launch, culler makes a single anonymous HTTPS request to GitHub for a small version file (at most once a day — no account, telemetry, or usage data). When a newer version exists, a quiet ● update vX.Y.Z note joins the corner readout and an "Update available" item joins the Help menu; clicking either opens the release notes in your browser. Nothing pops up, nothing installs itself, and if you're offline the check fails silently. Add disabled=1 to ~/.culler/update.conf to turn it off.
  • Server exports now match your screen. On an Immich source, J for a RAW+JPEG pair used to render the camera JPEG with your slider values — not the RAW render the develop panel was showing — so the uploaded picture could look different from what you graded. The export now bakes the same full RAW demosaic the panel shows, and a new server round-trip test proves the uploaded file is byte-for-byte what was rendered.
  • Re-uploading a pair can't double its stack. When part of a pair is already on the server (say the RAW, from an earlier upload), a new upload now joins the existing stack — newest JPEG in front, old members kept — instead of creating a second stack over the same photo. Re-running an already-finished batch changes nothing at all.
  • "Some photos didn't load" now says why. When timeline pages fail to load from a server, the warning names the failed pages and the server's actual error instead of only a count — and each failure is also logged to the console (look for culler: scan: lines in Console.app), so a recurring problem can actually be diagnosed.
  • The manual shows real photographs. Every screenshot in the manual is reshot with real RAW+JPEG pairs instead of generated test images.

0.4.1 — 2026-08-02

Field fixes from a real holiday-culling session against a live Immich server, same day as 0.4.0 — all remote browsing:

  • Portrait photos from a server now develop and export the right way up. Server previews arrive pre-rotated, but the original files — used for full zoom, RAW develop and export — don't; culler treated both the same, so portrait RAWs developed sideways and a compensating crop then baked wrong-way exports. Orientation is now tracked separately for the preview, the original, and the RAW member of a stack, so every path decodes upright.
  • Stacks appear while the library is still loading. Server-side stacks used to snap into place only after the whole scan finished — on a big library that read as duplicate RAW+JPEG pairs for a minute. The stack relations are fetched once up front, so photos group correctly the moment they stream in.
  • Big remote libraries open newest-first and stay put. The end-of-scan swap used to reverse the order out from under you (and leave the filmstrip showing stale thumbnails).
  • Re-exporting an edit (J) replaces your previous culler edit on the server instead of piling up a new version each time — and the new render joins the albums the photo was already in, so albums keep showing it. A camera pair inside a server stack keeps its stack identity too: the re-render joins the real stack (edit + JPEG + RAW), never a partial one that would orphan the RAW.
  • If stack information can't be loaded (a key without permission, a slow server), the scan now says so in the warning pill instead of silently showing everything unstacked.
  • Fixed: the × that removes a saved source flickered away under the pointer and the click opened the source instead.

0.4.0 — 2026-08-02

culler goes public. Downloads, the manual and these release notes now live at https://mertenssander.github.io/culler-releases/ — no invitation needed. And a field session against a real Immich server shaped a batch of upload improvements:

  • Uploads show progress and can be cancelled. The batch panel shows a live "Uploading N of M" with a progress bar, plus a Cancel button that finishes the photo in flight and then stops — no half-uploaded pair, and re-running is safe (the server recognizes what's already there). While the panel is closed, the batch's row in the top-right pill carries the same ✕.
  • Pick which server an upload goes to. With several Immich servers configured, the batch panel gains a Server picker — no silent default — and album choices follow the chosen server. The completion summary names where everything went.
  • Sources have names. The Immich form takes an optional name ("Home NAS" reads better than an IP in the server picker), and R renames any saved source in place.
  • RAW+JPEG pairs stack with the JPEG as the cover on the server, matching what culling shows you.
  • "Uploaded, but…" is a warning now, not a failure. When photos land but stacking or the album add fails — commonly an API key minted before your server knew about stacks; the manual's permission table covers it — the batch says so honestly instead of calling uploaded photos failed.
  • culler now runs on Intel Macs: releases are universal binaries.

0.3.0 — 2026-08-02

Buttons that teach their keys. A commissioned design exploration became culler's new edge chrome — every mouse control now shows the keyboard shortcut it stands for, then gets out of your way.

  • The rail (left edge): the current mode's verbs as keycap buttons — Pick, Reject, Clear, Rate, Grid, Compare, Filter while culling. Hovering teaches; the Filter and Rate buttons open real palettes (click a filter to jump straight to it; click a star chip). Buttons you've used about five times politely dim — the rail retires itself as you learn. ‹‹ collapses it to a thin line; rest the pointer on the line to bring it back.
  • The spine tabs (right edge): CULL · DEVELOP · CROP · BATCH name the workflow. Click to switch; rest on a tab and a palette fires that mode's one-shot actions (auto tone, reset…) — from anywhere.
  • The develop panel grew up: Auto / Reset / Match JPEG as a full-width row under the title, Copy / Paste / Before-After at the foot, keycap chips on everything, and the sliders scroll on small windows instead of clipping.
  • Overviews got stronger: Survey gained the Grid's peek (Space — a real loupe with zoom, winnowing keeps working), both overviews now accept filter changes in place (the grid re-points live, Survey re-deals), every mode hop works uniformly from both (E C V M S, plus K⇄N between them), and A reaches the batch panel from each. Persistent styled key-hint strips replace the old status-line text that any action would overwrite.
  • New filter: Picks + unrated — everything except your rejects, in the F cycle right after Picks and in the Filter menu.
  • The old bottom action dock is retired — everything it did lives on in the rail, the spines, and the ⋯ menu (now beside the rail, styled like the palettes).
  • Fixed: the develop pane could slowly widen until it covered the window.

0.2.1 — 2026-07-30

  • Server-side ratings now show up. Stars set in Immich's own web app (or by any other tool) were silently invisible when browsing a server: real servers report the rating in a different place than culler read.
  • Archive now works against a real server. The batch Archive action used a legacy API field that current Immich accepts and then ignores — archived photos now actually leave the timeline.
  • The Immich form teaches the API key: where to create one (Account Settings → API Keys) is written right under the field, and the manual gained a permission table for locked-down keys.
  • Under the hood: every release is now built by a pipeline that must first pass a live integration suite against a real Immich server — the two fixes above are what its first run caught.

0.2.0 — 2026-07-30

  • Batch from the grid: press A inside the Grid view (K) to open the Batch panel without leaving the grid — decide what happens to your picks and rejects while the whole set is in view. Marking keys keep working beside the open panel; A closes it again.
  • Menu bar knows the grid: while the grid is open, menu items that don't apply are greyed out (previously a menu click could stack Compare or a filter change on top of the grid). Batch… and Auto-advance stay enabled — their keys work in the grid.
  • Clearer scan progress: the top-right pill now says "Scanning photos" while a server timeline streams in. That count is culler reading the server's catalog — image bytes are only ever fetched around where you're looking, never the whole library.
  • Lower memory in long grid scrolls (thumbnail cache tuned down).
  • Manual: installation now leads with the DMG; the Immich chapter explains what the scan does and doesn't download.

0.1.0 — 2026-07-29

First packaged release — a native macOS app for extremely fast, keyboard-driven culling of RAW+JPEG photo pairs, with develop baked in.

  • JPEG-first culling: flags, stars, color labels, filters — everything writes to standard XMP sidecars, originals untouched.
  • Develop on the RAW: opening the develop panel demosaics the RAW (Sony in-camera lens correction included); white balance in real Kelvin, tone/curve/vignette, Match JPEG one-click fit.
  • Multi-photo tools: Compare (V), Survey (N), Match Look (M — grade one photo, the whole burst follows), and the Grid view (K — live overview with a progress tally, Space peeks any photo full-size).
  • Sources: local folders, SD cards, network shares, and Immich servers (browse, cull with live sync, upload/download with stacking).
  • Mouse path for new users: action dock, ▾ menu, clickable stars, edge navigation — all invisible until the mouse moves.
  • Native menu bar, JPEG export with full EXIF carry-over, batch copy/move/trash/upload.
